# Revisión de pruebas · 23 de noviembre de 2026

Revisión del código web/API, pruebas locales y base PostgreSQL de pruebas. No se desplegó a Vercel.

## Correcciones
- **Media — Peticiones de wallet malformadas:** JSON incompleto, null, arrays y valores primitivos devolvían 503. Ahora devuelven 400 antes de contactar con la API.
- **Media — Sesión expirada con respuesta no JSON:** una respuesta HTML con estado 401 provocaba un error de parseo antes de limpiar la sesión de la interfaz. Ahora se notifica la expiración y se conserva el estado HTTP en ApiError.
- **Media — Respuestas HTML de un proxy:** ahora muestran un error legible, en lugar del error interno de JSON.parse.
- **Media — Creación de usuarios sin acceso:** el panel todavía ofrecía correo y contraseña aunque la app solo admite wallet. Se retiró esa acción y la API la rechaza fuera del entorno de pruebas. Se mantiene la edición de usuarios existentes. Las invitaciones de wallets siguen pendientes.
- **Baja — Edición de rol:** el formulario buscaba roleId, pero la API devuelve role.id. Ahora conserva el rol actual al editar.

## Evidencia
Se añadieron siete casos de regresión que fallaron antes de las correcciones y pasaron después:
- tests/integration/web-wallet-route.test.ts: cinco cuerpos inválidos.
- tests/integration/web-client.test.ts: 401 y 503 con HTML.

Resultados locales:
- pnpm check: tipos, 36 pruebas de lógica, validación Prisma y compilación web/API/exportación Expo correctas.
- pnpm test:integration: 55 pruebas HTTP con PostgreSQL correctas.
- pnpm smoke: sesión por firma, cookies, origen, revocación, cuerpos inválidos y rechazo de creación de usuarios por correo correctos.

## Publicación
git.deploymentEnabled está deshabilitado en las configuraciones de web y API. Los cambios se entregan mediante GitHub, sin despliegue.

## Límites
No se validaron extensiones de wallet reales ni dispositivos Android/iOS. No se repitieron las pruebas Rust o del validador Solana en esta revisión, porque no se modificó el programa. Estos resultados no certifican que la aplicación carezca de otros defectos.

La alerta de MetaMask no se considera resuelta por estos cambios. No se debe ignorar la protección; una clasificación del proveedor requiere su revisión. Tampoco se ha comprobado el estado actual de PostgreSQL remoto ni de la API publicada.
